# AA 宏观量与方向性 halo 重叠试验（2026-11-23）

## 范围与实现

本试验在独立分支 `codex/lbm3d-aa-overlap-investigation` 进行，基点为 P2 提交 `5eec2af`，未修改 P2 主工作树。受测对象是单层、全周期、FP64 D3Q19 TGV 的 AA 存储路径；P1 双缓冲路径仍使用原来的 `Fill` 与整块宏观量计算。分布函数仍是一份 19 分量 `MultiFab`，宏观场仍为 4 分量；没有新增整场暂存、改变 BGK 公式或调整浮点求和顺序。

`DirectionalHalo` 的 AMReX 通信标签和远端 peer 列表在构造时建立并缓存。AA 偶步 `Fill` 从接收列表、奇步 `ScatterAA` 从反向的发送列表读取入向 peer 数。仅当入向 peer 多于一个时，碰撞与发送打包后，在等待接收期间异步计算每个 FAB 缩小一格的内部宏观量。随后同步这些 GPU stream、完成远端解包，再用一次紧凑索引 GPU 核计算六个互不重叠的边界面。内部单元所需的 19 个分布函数均由同一 FAB 产生；边界单元在 halo 完成后才读取。单卡与单 peer 配置保留原来的整块宏观量 GPU 核。所有配置仍走相同的一层方向性 halo 通信路径。

## 剖析与优化选择

先对原 AA 二进制做四 rank Nsight Systems 2023.2.3 跟踪，运行 140 步并统计第 101～140 步，使用正式 UCX 运行库。偶步、奇步在四个 rank 上的“本地 halo GPU 复制结束至最后接收等待结束”中位数为 **0.936～1.018 ms/步**；完整宏观量 GPU 阶段跨度为 **1.172～1.267 ms/步**。因此存在可覆盖的等待窗口。原始 SQLite 位于工作站 `deps/lbm3d-aa-overlap-20261123/runs/profile-baseline-4strong-ucx/`。这些 profiler 时间受跟踪扰动，不作为无剖析步时。

第一版让边界 GPU 核遍历整个 FAB 并跳过内部单元：三档强扩展筛选为 14.636/8.785/4.534 ms/步，双卡退步。第二版用两次三 Box 启动处理六个边界面：14.680/8.613/4.451 ms/步，仍未过四卡门槛；其四 rank 跟踪中边界阶段跨度仍为 **0.493～0.564 ms/步**。最终版将六面映射到每 FAB 一次紧凑线性索引启动，且只在多个入向 peer 时启用重叠。前两版的实验日志保留于远端隔离目录，不计入下表正式对照。

## 三轮交错强弱扩展

工作站为 4×Tesla V100-SXM2-32GB，AMReX 26.11、CUDA 12.2、`sm_70`、Release CUDA `-O3 -DNDEBUG`、`LBM_ENABLE_IBM=OFF`、`LBM_TIMING=ON`。运行显式设置定制 Open MPI 4.1.8 与 UCX 1.21.1 的 `LD_LIBRARY_PATH`，`UCX_TLS=self,sm,cuda_copy`，`mpirun --mca pml ucx --mca pml_ucx_tls any --mca btl ^uct`。1/2/4 卡分别映射 0、0/2、0/1/2/3，按 NUMA 绑定。强扩展固定全局 256³，弱扩展固定每卡 256³；`max_grid_size=64`、`blocking_factor=8`。每次预热 100 步、计时 500 步，质量检查每 100 步，不写 plotfile 或 checkpoint。

每个方案各运行三轮，GPU 顺序为 1→2→4、4→2→1、1→2→4；同档 GPU 的基线/候选顺序逐轮为基线→候选、候选→基线、基线→候选。下表是各自三轮中位数，效率均以**同一方案自己的单卡步时**计算。

| 测试与方案 | 1 卡 ms/步 | 2 卡 ms/步 | 4 卡 ms/步 | 2 卡效率 | 4 卡效率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 强扩展基线 | 14.619751 | 7.596237 | 4.704724 | 96.23% | 77.69% |
| **强扩展候选** | **14.640607** | **7.590888** | **4.191897** | **96.44%** | **87.31%** |

候选四项效率均**严格大于 85%**。四卡强扩展相对同批基线减少 **0.512827 ms/步（10.9%）**；四卡弱扩展增加 **0.243306 ms/步（1.52%）**，仍高于门槛。全部 36 次运行正常完成，末步质量等于对应全局格点数；每个运行目录仅含 `run.log`。[强扩展原始记录](../Performance/p2-aa-overlap-paired-strong-20261123.json)与[弱扩展原始记录](../Performance/p2-aa-overlap-paired-weak-20261123.json)包含每次命令、二进制与输入哈希、日志路径、步时、质量和无全场文件检查。一次更早的交错批次遇到其他进程占用 GPU0，立即停止并整体排除；其数据没有进入本表。
